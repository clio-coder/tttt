## 3. AlexNet [p5–22]

8층 CNN = **합성곱 5층 + FC 3층**. 출력 크기는 9/28의 공식 $(N-K+2P)/S+1$ 으로 계산한다 (슬라이드: "(Feature size − kernel size)/stride + 1").

| 층 | 설정 | 출력 | 계산 |
| --- | --- | --- | --- |
| Input | | 227×227×3 | |
| Conv1 + ReLU | 필터 96개, 11×11, stride 4, pad 0 | 55×55×96 | $(227-11)/4+1=55$ |
| MaxPool1 | 3×3, stride 2 | 27×27×96 | $(55-3)/2+1=27$ |
| Norm1 | | 27×27×96 | |
| Conv2 + ReLU | 256개, 5×5, stride 1, pad 2 | 27×27×256 | $(27-5+4)/1+1=27$ |
| MaxPool2 | 3×3, stride 2 | 13×13×256 | $(27-3)/2+1=13$ |
| Norm2 | | 13×13×256 | |
| Conv3 + ReLU | 384개, 3×3, stride 1, pad 1 | 13×13×384 | $(13-3+2)/1+1=13$ |
| Conv4 + ReLU | 384개, 3×3, stride 1, pad 1 | 13×13×384 | 〃 |
| Conv5 + ReLU | 256개, 3×3, stride 1, pad 1 | 13×13×256 | 〃 |
| MaxPool3 | 3×3, stride 2 | 6×6×256 | $(13-3)/2+1=6$ |
| FC6 | 9216 × 4096 | 4096 | $6\cdot6\cdot256=9216$ (flatten) |
| FC7 | 4096 × 4096 | 4096 | |
| FC8 | 4096 × 1000 | 1000 | 클래스 1000개 |

**특징 네 가지** [p18–22]
1. **ReLU를 쓴 첫 CNN.** 그전에는 sigmoid나 tanh → saturating gradient → 학습이 느리다 (9/21 활성화 함수 재검토와 같은 이유).
2. **첫 층의 큰 stride(4).** feature 크기를 줄여 계산을 아낀다 (약 3G GPU 메모리로 학습).
3. **Normalization layer** (Local Response Normalization). 최근 CNN에서는 쓰지 않는다.
4. **FC 층에 Dropout 0.5** — 과적합 방지. "**FC layers are extremely expensive!**"

**(보충) 가중치 수를 직접 세어 보면** (슬라이드 표 기준, bias 제외)

| 층 | 계산 | 가중치 수 |
| --- | --- | --- |
| Conv1 | $11\cdot11\cdot3\cdot96$ | 34,848 |
| Conv2 | $5\cdot5\cdot96\cdot256$ | 614,400 |
| Conv3 | $3\cdot3\cdot256\cdot384$ | 884,736 |
| Conv4 | $3\cdot3\cdot384\cdot384$ | 1,327,104 |
| Conv5 | $3\cdot3\cdot384\cdot256$ | 884,736 |
| **합성곱 합** | | **약 3.7M** |
| FC6 | $9216\cdot4096$ | 37,748,736 |
| FC7 | $4096\cdot4096$ | 16,777,216 |
| FC8 | $4096\cdot1000$ | 4,096,000 |
| **FC 합** | | **약 58.6M (전체의 약 94%)** |

합성곱 5층을 다 합쳐도 FC6 하나의 10분의 1이다. 가중치 공유(9/28)가 파라미터를 얼마나 줄이는지, 그리고 GoogLeNet이 왜 FC 층을 없앴는지(§5)가 이 표에서 보인다.

## 4. ZFNet과 VGGNet [p23–25]

- **ZFNet** [p24]: AlexNet과 같은 구조에서 숫자만 조정했다.
  - CONV1: 11×11 stride 4 → **7×7 stride 2**
  - CONV3, 4, 5: 필터 384, 384, 256개 → **512, 1024, 512개**
  - top-5 오류 16.4% → 11.7%
- **VGGNet** [p25]: **더 작은 합성곱 필터로 더 깊은 망**을 만든다 (19층, 7.3%). 슬라이드는 이 한 줄뿐이다.
  - (보충) 작은 필터로 깊게 쌓는 이유: 3×3 합성곱을 두 번 쌓으면 5×5 영역을 본다. 채널 수가 $C$로 같을 때 가중치는 $2\cdot9C^2=18C^2$ 으로 5×5 한 층의 $25C^2$ 보다 적고, 비선형 함수는 한 번 더 들어간다.

## 5. GoogLeNet과 inception module [p26–42]

**GoogLeNet** [p27]
- **더 깊다**: 22층 (VGG는 16층). 각 층이 작은 망(**inception module**)으로 되어 있다.
- **효율적인 파라미터 구성**: **FC 층이 없다.** AlexNet보다 파라미터가 12배 적다.
- 성능: 7.3%(VGGNet) → 6.7% top-5 오류

**Inception module** [p28]
- 크기가 다른 필터를 **나란히** 쓴다: 1×1, 3×3, 5×5 합성곱과 max pooling (stride 1)
- 여러 receptive field의 정보를 모은다.
- 모든 필터의 반응을 **깊이 방향으로 이어 붙인다**(depth-wise concatenation).

**1×1 convolution** [p29–32]
- $W\times H\times C$ feature에 1×1×C 필터 하나 → $W\times H\times1$. 필터 $K$개 → $W\times H\times K$.
- 이것은 **픽셀별 임베딩**이다: 각 픽셀의 $C$차원 벡터를 $K$차원으로 보낸다. **$K\lt C$이면 차원을 줄인다.**

**Naive inception** [p33–36] 입력 28×28×256

| 가지 | 설정 | 출력 | 가중치 |
| --- | --- | --- | --- |
| 1×1 conv (128) | $s=1$, $p=0$ | 28×28×128 | $1\cdot1\cdot256\cdot128=32{,}768$ |
| 3×3 conv (192) | $s=1$, $p=1$ | 28×28×192 | $3\cdot3\cdot256\cdot192=442{,}368$ |
| 5×5 conv (96) | $s=1$, $p=2$ | 28×28×96 | $5\cdot5\cdot256\cdot96=614{,}400$ |
| 3×3 maxpool | $s=1$, $p=1$ | 28×28×256 | 0 |
| **이어 붙이면** | | 28×28×**672** | 합 **1,089,536 ≈ 1090k** |

- 네 가지 모두 공간 크기가 28×28로 같아야 이어 붙일 수 있다. $s=1$, $p=(F-1)/2$ (same padding)이라 유지된다. 예: maxpool $(28-3+2)/1+1=28$.
- 출력 채널: $128+192+96+256=672$
- **문제** [p36]: feature 차원이 너무 커진다 → 윗층의 파라미터가 늘고 메모리가 더 든다. (보충) pooling 가지는 입력 채널 256을 그대로 내보내므로 module을 지날 때마다 채널이 늘기만 한다.

**Bottleneck을 넣은 inception** [p37–40] — 3×3·5×5 합성곱 **앞**과 pooling **뒤**에 1×1 conv (64)를 끼운다.

| 가지 | 출력 | 가중치 |
| --- | --- | --- |
| 1×1 conv (128) | 28×28×128 | $1\cdot1\cdot256\cdot128=32{,}768$ |
| 1×1 conv (64) → 3×3 conv (192) | 28×28×64 → 28×28×192 | $256\cdot64+3\cdot3\cdot64\cdot192=16{,}384+110{,}592$ |
| 1×1 conv (64) → 5×5 conv (96) | 28×28×64 → 28×28×96 | $256\cdot64+5\cdot5\cdot64\cdot96=16{,}384+153{,}600$ |
| 3×3 maxpool → 1×1 conv (64) | 28×28×256 → 28×28×64 | $256\cdot64=16{,}384$ |
| **이어 붙이면** | 28×28×**480** | 합 **346,112** (슬라이드: 약 330k) |

- 출력 채널: $128+192+96+64=480$ (672에서 줄었다)
- 가중치: 3×3 가지가 442,368 → 126,976, 5×5 가지가 614,400 → 169,984. **비싼 큰 필터가 256채널이 아니라 64채널을 입력으로 받기 때문**이다.
- 슬라이드 결론: Naive inception 약 **1090k** → bottleneck 약 **330k**

**전체 구조** [p41–42]: 앞쪽은 단순한 합성곱 층을 쌓고, 위쪽은 inception module을 쌓으며 가끔 downsampling한다.

## 6. 깊이와 성능, ResNet [p43–51]

**더 깊으면 더 좋은가** [p44–46]
- 지금까지는 깊을수록 좋았다: AlexNet(8층) → VGGNet(16층) → GoogLeNet(22층).
- 그런데 CIFAR-10에서 **56층 plain 망이 20층보다 test error가 높다.** 파라미터가 늘어서 과적합한 것일까?
- 아니다. **56층은 training error도 더 높다.** → "It's **NOT** an overfitting problem!"
  - (보충) 과적합이라면 training error는 낮고 test error만 높아야 한다 (9/9 다항회귀 $M=9$의 모양). 여기서는 학습 데이터조차 못 맞춘다.

**왜 더 깊은 망이 더 나쁜가** [p47]
- **이론상** 깊은 망은 학습 데이터를 맞추는 데 얕은 망보다 **적어도 같거나 좋아야** 한다.
  - (보충) 논증: 얕은 망을 그대로 복사하고 나머지 층을 **항등함수**로 두면 같은 함수가 된다. 그러니 깊은 망의 최소 training error는 얕은 망보다 클 수 없다.
- 하지만 큰 망은 **최적화하기가 훨씬 어렵다.** 깊은 망의 잠재적 문제:
  - **Gradient vanishing** — 기울기 노름이 0에 가까워진다.
    $$\frac{\partial J(W)}{\partial h^{(l)}}=\frac{\partial J(W)}{\partial h^{(L)}}\frac{\partial h^{(L)}}{\partial h^{(L-1)}}\frac{\partial h^{(L-1)}}{\partial h^{(L-2)}}\cdots\frac{\partial h^{(l+1)}}{\partial h^{(l)}}$$
    (보충) 9/21 역전파의 "upstream × local"을 층마다 반복한 것이다. 곱하는 인자가 많을수록, 각 인자가 작을수록 아래층에 닿는 기울기가 작아진다.
  - **Covariate shift** — 아래층의 작은 변화가 깊은 층에서 큰 변화로 이어진다 (9/23 internal covariate shift).

**Residual connection** [p48]
- 핵심: **shortcut connection**을 더해 **항등함수를 쉽게 배울 수 있게** 한다.

| | Plain 층 | Residual block |
| --- | --- | --- |
| 구조 | $x$ → conv → relu → conv | $x$ → conv → relu → conv, 그 결과 $F(x)$에 $x$를 더한 뒤 relu |
| 배우는 것 | $H(x)$ 전체 | 잔차 $F(x)$, 출력은 $F(x)+x$ |

- "In degenerated case, we can learn identity mapping by setting $F(x)=0$" — 층이 할 일이 없으면 **가중치를 0으로 두기만 하면** 항등함수가 된다. 위 (보충) 논증의 "나머지 층을 항등함수로"를 쉽게 만들어 준다.
- "Optimization is much easier by allowing **bypassing gradients** through identity connection."
  - (보충) $y=x+F(x)$ 이면 $\dfrac{\partial y}{\partial x}=I+\dfrac{\partial F}{\partial x}$. 위 곱의 각 인자가 "작은 Jacobian"에서 " $I$ + Jacobian"으로 바뀌므로, $\partial F/\partial x$가 작아도 기울기가 $I$를 타고 그대로 내려간다. 9/21 gate 패턴으로 보면 덧셈 노드는 **gradient distributor**라서 upstream 기울기를 shortcut 쪽으로 그대로 넘긴다.

**Residual block의 두 종류** [p50]

| | Plain residual block | Bottleneck residual block |
| --- | --- | --- |
| 입력 | 64채널 | 256채널 |
| 구성 | 3×3, 64 → relu → 3×3, 64 | 1×1, **64** → relu → 3×3, **64** → relu → 1×1, 256 |
| 채널 | 그대로 | 256 → 64 → 256 |
| (보충) 가중치 | $2\cdot3\cdot3\cdot64\cdot64=73{,}728$ | $256\cdot64+3\cdot3\cdot64\cdot64+64\cdot256=69{,}632$ |

- (보충) 256채널에서 3×3 합성곱을 두 번 그대로 하면 $2\cdot9\cdot256\cdot256=1{,}179{,}648$개가 든다. bottleneck은 그 약 17분의 1로, 64채널 plain block과 비슷한 비용이다. inception의 1×1 bottleneck(§5)과 같은 요령이다.

**결과** [p49, p51]
- 구조 그림: VGG-19, 34층 plain, 34층 residual (plain에 shortcut을 더한 것)
- CIFAR-10: **plain 망**은 깊을수록(20 → 56층) 오류가 커지고, **residual 망**은 깊을수록(20 → 110층) 오류가 줄어든다. (점선 = training, 실선 = testing)

## 7. Saliency map [p52–55]

- **Saliency**: 특히 눈에 띄거나 중요한 성질. 주변과 구별되어 두드러지는 정도. [p52]
- **Saliency map**: 이미지의 **어느 부분이 예측에 가장 크게 기여하는지** 본다. [p53]
  - Forward: 이미지 $I$ → 클래스 점수 $S_c(I)$ (예: "dog")
  - Backward: $\dfrac{\partial S_c(I)}{\partial I}$ — **픽셀이 변할 때 점수가 얼마나 민감하게 변하는가** → 분류에 대한 픽셀의 기여도
- 연쇄법칙 [p54–55]: 층별 feature를 $F^{(1)},\dots,F^{(L)}$ 이라 하면

$$\frac{\partial S_c(I)}{\partial I}=\frac{\partial F^{(L)}}{\partial F^{(L-1)}}\frac{\partial F^{(L-1)}}{\partial F^{(L-2)}}\cdots\frac{\partial F^{(1)}}{\partial I}$$

- (보충) 학습 때의 역전파와 계산은 같고 **미분하는 대상만 다르다**: 학습은 손실을 가중치로 미분하고, saliency는 클래스 점수를 **입력 픽셀**로 미분한다. 역전파 한 번이면 이미지와 같은 크기의 기울기가 나온다.
- 슬라이드 예: 요트, 개, 과일, 원숭이, 소 이미지에서 물체가 있는 부분이 밝게 나온다. [p55]
